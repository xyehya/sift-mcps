## 2024-05-18 - Avoid `new Date()` Object Allocation Overhead in Hot Loops
**Learning:** Instantiating `new Date(ts)` in hot loops, like array sorts, maps, or UI render cycles for thousands of timestamp rows, causes massive performance overhead due to object allocation and garbage collection. Often times we're just comparing timestamps or slicing strings, and the object allocation is redundant.
**Action:** When extracting date or time parts, use fast-path logic to check if the input is already a valid ISO string and do simple string slicing (e.g. `substring(0, 10)`), falling back to `new Date(ts).toISOString()` only when necessary. For comparing timestamps, parse to epoch integer rather than allocating a `Date` object. Use helpers like `extractDate`, `extractTime`, and `parseTimestamp` from `@/components/common/entity-utils`.
